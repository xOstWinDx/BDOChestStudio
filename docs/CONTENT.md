# Сундуки, предметы и ресурсы

## Новый сундук

Добавьте класс в `src/bdo_sim/content/chests.py`:

```python
class ExampleChest(AbstractChest):
    id = "example_chest"
    name = "Пример сундука"
    name_en = "Example Chest"
    icon = "icons/chest.svg"
    rarity = "chest"
    crown_value = None

    @classmethod
    def loot_table(cls):
        return (
            Loot(items.CronStone, quantity=100, chance=90),
            Loot(ButterflyChest, quantity=1, chance=10),
        )
```

Импорты `AbstractChest`, `Loot`, `items` уже есть в этом модуле.
`__init_subclass__` регистрирует класс автоматически. Если класс находится в новом
модуле, импортируйте модуль в `content/__init__.py`, чтобы сборщики exe его видели.

ID уникален, на английском в `snake_case`. Иконка и названия обязательны. Методы
таблиц — classmethod, чтобы можно было ссылаться на себя и классы ниже по файлу.

| База | Таблицы | Семантика |
| --- | --- | --- |
| `AbstractChest` | `loot_table()` | Один результат; chance — относительный вес |
| `AbstractBonusChest` | `guaranteed_loot()`, `bonus_loot()` | Все гарантированные награды + независимые бонусы |
| `AbstractChainChest` | `chain_stages()` | Переходы по этапам, награды при остановке |
| `AbstractItem` | Нет | Конечный предмет |

Гарантированная упаковка одного предмета может быть сразу конечным предметом:
не создавайте отдельный шаг открытия без необходимости. Пример — советы Валкса.

`quantity` — положительное целое число; `chance` — конечное число 0–100.
Во взвешенной таблице проценты совпадают с весами только при сумме 100.
Бонусные проценты независимы и не обязаны суммироваться до 100.
Для гарантированных наград и наград этапа `chance` должен быть 100.
Циклы этапов запрещены, рекурсивный дроп сундуков допустим и ограничен движком.

## Предметы и стоимость

Классы предметов находятся в `src/bdo_sim/content/items.py`.
`crown_value` — оценка одной единицы в кронах. `None` означает неизвестную стоимость,
а не ноль. Текущие оценки и таблицы унаследованы от прототипа, без проверки по игре.
Изменение ID ломает ссылки на предмет в старой истории; автоматического сопоставления нет.

## Изображения

1. Положите PNG, JPG, WebP или SVG в `src/bdo_sim/assets/icons/`.
2. Укажите в классе относительный путь: `icon = "icons/my_chest.png"`.
3. Перезапустите исходники или пересоберите exe.

Для PNG удобны прозрачный фон и размер 128–256 px. Варианты количества одного предмета
могут явно использовать один файл. Пути разрешаются относительно пакета, а не рабочей папки.
Новый файл должен иметь понятное имя, источник и разрешение на использование;
дополните [перечень ресурсов](ASSETS.md).

## Редкость

`Loot.rarity` возвращает enum `Rarity` по значению chance. UI использует фактическую
вероятность: нормализует веса, а для цепочек учитывает достижение и остановку этапа.
Редкость относится к конкретному выпадению с его количеством, не к цене предмета.

| Шанс | Редкость / рамка |
| --- | --- |
| >35% | Common / нейтральная |
| >15–35% | Uncommon / зелёная |
| >5–15% | Rare / синяя |
| >1–5% | Epic / жёлтая |
| >0,1–1% | Legendary / оранжевая |
| ≤0,1% | Mythic / красная |

Бонусные сундуки показывают фактический дроп карточками, обычные — рулеткой.
Бабочка и золотой сундук закреплены первыми в каталоге. Остальные сортируются по
ожидаемому числу вложенных открытий на шесть уровней с учётом количества и шансов.

## Переводы и темы

UI-строки находятся в `src/bdo_sim/assets/locales/{ru,en}.json`, раздел `ui`.
Подстановки `{name}`, `{n}` и другие должны совпадать в обоих языках.
Названия предметов задаются в классах: `name` и `name_en`.

Темы описаны в `src/bdo_sim/ui/theme.py`: ключи `midnight`, `ocean`, `ember`, `daylight`.
Цвета основных текстов и поверхностей проверяются на контраст. Звуки — локальные WAV
в `assets/sounds/`, воспроизводятся через общий `ui/audio.py`.
